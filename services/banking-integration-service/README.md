# banking-integration-service

Generated by HexaForge as a Java 21 / Spring Boot 3.5.16 single-module hexagonal service.

## Banking provider POC

The service exposes two canonical APIs and calls a simulated external bank:

```text
GET  /api/v1/accounts/{accountId}
POST /api/v1/transfers
```

From the repository root, start the service and its WireMock bank:

```bash
docker compose -f compose.banking.yaml up -d --build
scripts/banking-smoke-test.sh
docker compose -f compose.banking.yaml down
```

Example requests:

```bash
curl -i http://localhost:8082/api/v1/accounts/ACC-001 -H 'Request-ID: BANK-GET-001'

curl -i http://localhost:8082/api/v1/transfers \
  -H 'Content-Type: application/json' -H 'Request-ID: BANK-POST-001' \
  -d '{"fromAccount":"ACC-001","toAccount":"ACC-002","amount":100000,"currency":"VND","reference":"ORDER-SUCCESS-001"}'
```

WireMock listens on `9103` for debugging. Use account `ACC-TIMEOUT` or a transfer
reference containing `TIMEOUT` to simulate a slow bank. Unknown accounts return
404; transfer references without `SUCCESS` return a bank rejection.


```bash
./mvnw clean verify
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

- Swagger UI: <http://localhost:8080/swagger-ui.html>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>
- Health: <http://localhost:8080/actuator/health>
- Liveness: <http://localhost:8080/actuator/health/liveness>
- Readiness: <http://localhost:8080/actuator/health/readiness>


Domain is plain Java. Application use cases depend on domain and outbound ports. Inbound REST adapters call inbound ports; outbound adapters implement outbound ports. Infrastructure owns wiring, i18n, error response models, and observability. ArchUnit verifies the dependency boundaries in every build.


```bash
curl -i -H 'Request-ID: REQ-123' -H 'Accept-Language: en' http://localhost:8080/api/v1/items/item-1
```

Success:

```json
{"id":"item-1","name":"Sample item"}
```

English error (`/api/v1/items/missing`):

```json
{"code":"BNK-ITEM-001","message":"Item not found","traceId":"...","requestId":"REQ-123","timestamp":"2026-09-18T06:30:00Z","details":[]}
```

Vietnamese uses `Accept-Language: vi` and keeps the code stable:

```json
{"code":"BNK-ITEM-001","message":"Không tìm thấy mặt hàng","traceId":"...","requestId":"REQ-123","timestamp":"2026-09-18T06:30:00Z","details":[]}
```

To add a domain, create plain domain types, inbound/outbound ports, a use case, then boundary adapters and infrastructure wiring. To add inbound adapters, call only inbound ports. To add outbound adapters, implement an outbound port. To remove the sample, delete all `Item*` files, `InMemoryItemAdapter`, its bean wiring/messages, and related tests.

Before production, add a complete security design, real persistence/client adapters where required, telemetry export, secret management, deployment limits, and operational testing. Actuator exposes only health, info, and metrics by default.
